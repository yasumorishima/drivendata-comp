# 公開 LB 2 位（botabun, 0.2021）の Shared work を読んだ記録（2026-10-21）

出典：https://github.com/hatrieukim/whats-up-docs （MIT。リーダーボードの Shared work のリンク）。コードは写していない。

## 中身
- 診断は私たちと同じ：著者は本文の自分の文を要旨に再利用する（65% の論文で 8 語以上の一致）。言い換えると点を失う。文の選び方の上限（オラクル）は約 0.35。
- 方式：論文を掃除（引用・表・注を落とす）→ 冒頭・途中の手がかり文・結論を番号付きで LLM に渡す →
  **LLM（Gemini 3.8 Flash、有料 API）は文番号を 5〜10 個選ぶだけ** → その文を原文のまま論文順に並べ、**250 語**で打ち切る。
- 測り方：固定分割 dev 150 で 0.2224、公開 LB 0.2021（dev が LB より 0.02 高い）。プロンプトの調整は 1 回 +0.002 程度まで頭打ち。
- 未着手として挙げている案：強いモデルで選ぶ・全文に点を付けて点と長さで選ぶ・要旨の長さを予測。

## 私たちへの示唆
- 私たちの v2〜v4 は「全文に点を付けて点と長さで選ぶ」に当たる（彼らの未着手案）。CV は LB より約 0.005 低く出る（逆向き）。
- 有料 API は使わない方針なので、LLM に文を選ばせるなら無料 GPU の Qwen 7B。ゼロショットの選択がどこまで効くかは未検証。
- 予算 250 語：私たちの CV では 190 と 210 でほぼ同じだった。v4 で選び方が変わったので、もう一度 190/230/250 を比べる価値はある（ただし小手先にならないよう、v4 の特徴と合わせて 1 回で決める）。
