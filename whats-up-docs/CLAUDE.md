**提出は 1 日 3 本（UTC 0 時で回復）。** 毎日 3 本を 1 本ずつ、結果を見てから次を出す（repo の CLAUDE.md）。

## 課題

- 社会科学の論文本文（Markdown、中央値 5,800 語）から、著者の要旨（中央値 182 語）を作る。学習 1,000 本・テスト 345 本。
- 評価：文書ごとの ROUGE-2 F1（2 語の並びの一致）の平均。
- 提出：`paper_id,summary` の CSV。外部データ・学習済みモデルは権利があれば可（External data with rights）。
- 🔴 テスト論文の本物の要旨をネットから引くのはしない（公開 LB 1 位 0.98 はこれと見る。課題の趣旨に反する）。

## 🎯 上位への道筋（2026-10-20）

- 公開 LB（10-20）：2 位 0.2021・3 位 0.1800・5 位 0.1742・8 位 0.1659（1 位 0.982 は除外して考える）。**目標は 0.21 以上＝実質 1 位。**
- 手元の物差し（学習 1,000 本の 5 分割 CV、`extractive.py cv`）：
  - 先頭 250 語：0.106。文を理想的に選んだ上限（貪欲オラクル）：0.342。
  - 教師あり抜粋（LightGBM で「要旨に入る 2 語の並びの割合」を予測→上位の文を 190 語まで）：**0.170**。
- 勝負どころ：ROUGE-2 は**要旨の言い回しをどれだけ再現するか**。抜粋の上限 0.34 と現状 0.17 の差が大きい。
  1. 抜粋側：文の選び方を良くする（文書内の順位を直接学ぶ ranking 目的・要旨の型「This paper / We find」の文を確実に拾う・長さを要旨の予測長に合わせる）。
  2. 生成側：無料の GPU（Kaggle T4）で 7B 級の LLM に、抜粋した文を材料として渡して要旨の形に書き直させる。学習 1,000 本で LoRA 微調整すれば要旨の言い回しを覚える。
  3. 2 つを比べ、文書ごとに良い方を選ぶ（または生成に抜粋を混ぜる）。
- 合格基準：CV 0.19 で LLM 版を出す。CV と LB の差を 1 本目で測る。

## LLM 版の記録

- 仕組み：`requests/kaggle-run.json` を push → `Kaggle Run` が入力 dataset（非公開 `yasunorim/dd-whats-up-docs-input`）を作り、
  kernel `yasunorim/dd-whats-up-docs-llm` を T4 で回し、出力を data-cache `kout-<name>` に置き、`results/kernel-<name>.md` に検証の点を記録。
  提出は `{"data": "kout-<name>", "script": "whats-up-docs/from_kernel.py"}` で Submit Prediction。
- **llm-v1（10-20）：Qwen2.5-7B-Instruct ゼロショット**（抜粋 450 語＋冒頭 350 語を渡して要旨を書かせる）。検証 100 本：
  抜粋 0.181 ／ LLM＋抜粋 80 語 0.168 ／ LLM のみ 0.147。
  - 考察：ゼロショットの LLM は**言い換える**ので、著者の要旨と共有する 2 語の並びが減る。ROUGE-2 では負ける。
    指示で「論文の語を使え」と書いても足りない。著者の要旨の書き方（どの文をどう縮めるか）を**学習させる**必要がある。

- **LLM の使い方の結論（10-21）**：LLM に要旨を書かせて出すのではなく、**LLM の要旨を「どの文を選ぶか」の手がかりに使う**。
  ゼロショット 7B の要旨で選び直すと +0.0065（検証）／ +0.0033（LB）。LoRA 1.5B の要旨で選び直すと逆に下がる（0.180→0.174）。

- **CPU で LLM を回す仕組み（10-21）**：`requests/llm-cpu.json` → `LLM on CPU`（Actions 20 本、llama.cpp の Qwen2.5-7B q4_k_m、1 本 70〜140 秒）。
  merge は `requests/llm-cpu-merge.json`（成果物 3 日）。llm-cpu-v1：1,313 本（学習 32 本は文脈超過で欠け、今は直した）。
  4bit の要旨は fp16 より著者の要旨に近いくらい（val 0.156 vs 0.147）＝量子化で質は落ちていない。
- LoRA v1（Qwen2.5-1.5B、900 本 2 epoch、`whats-up-docs/lora/`）：検証 0.109。流暢だが言い換える。**生成文は提出に使わない。**
- 公開 2 位の解法（`notes/whats-up-docs/public-2nd-botabun.md`）：有料 LLM に文番号を選ばせて原文のまま 250 語。私たちと同じ「選ぶ」方針。

## 次の一手（10-22〜）

1. **LLM の手がかりを増やす**：v4 の効きは「LLM が要旨で何を言うか」を示すこと。
   - 同じ論文に 2 本目の LLM 要旨（別の促し：「目的・データ・結果・含意を論文の文で」など）を作って特徴を足す。
